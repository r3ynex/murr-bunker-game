# Murr Bunker Game — путеводитель по исходникам

**Цель:** бесплатная портативная игра для компании друзей в духе «Бункера», но со своими механиками и оформлением. Основной клиент — **Rust + egui**, комнаты — **Cloudflare Worker + Durable Objects**, сборка Windows — **GitHub Actions**.

> **Важно:** это ранний прототип, а не полный аналог bunker-online.com. Дизайн пока технический. Не добавляй в репозиторий чужие платные паки, тексты и изображения без разрешения.

## 2. Как работает мультиплеер

```text
Murr-Bunker.exe
    |
    +-- POST /api/rooms                 создать новую комнату
    |        |
    |        +-- ответ { code, playerId, token }
    |
    +-- POST /api/rooms/CODE/join       присоединиться к комнате
    |        |
    |        +-- ответ { code, playerId, token }
    |
    +-- WS /api/rooms/CODE/ws?token=... постоянное соединение
             |
             +-- Cloudflare Durable Object (отдельный для каждого кода)
                   |-- список игроков, ведущий
                   |-- катаклизм, бункер, карты
                   |-- раунды и результаты голосования
                   |-- проверки прав и игровых команд
                   +-- выдача персонального состояния каждому игроку
```

**Durable Object — сервер-источник истины.** Клиент отправляет лишь действия. Браузер или EXE **не решает**, кто стал ведущим, какие карты выпали и сколько голосов набрал участник. Пока карта другого игрока не раскрыта, сервер **не отправляет** её текст посторонним.

Данные комнаты сохраняются в хранилище Durable Object. Нельзя путать это с бесконечным хранением партии: сейчас **нет** управления временем жизни комнат, миграции аккаунтов или восстановления токена после закрытия клиента.

### Где искать обработчики

В `server/src/index.js`:
- `fetch()` в стандартном экспорте Worker маршрутизирует HTTP-запросы;
- `Room.fetch()` создаёт комнату, добавляет участников и принимает WebSocket;
- `Room.view(state, viewerId)` формирует **персональный** вид комнаты (скрытые карты других участников отфильтрованы);
- `Room.broadcast()` отправляет обновлённое состояние всем;
- `Room.webSocketMessage()` проверяет и исполняет игровые команды;
- `Room.note()` сохраняет последние строки журнала;
- `Room.newPlayer()` выдаёт ID и уникальный токен.

**Очень важно:** если добавляешь приватную характеристику, проверяй её видимость в `Room.view()`. Нельзя просто отправлять всем весь объект `state`.

## 3. Где менять правила и контент

| Хочу изменить | Где искать |
| --- | --- |
| Минимальное количество игроков (сейчас 2 для теста) | `server/src/index.js`, ветка команды `start` |
| Максимальное количество игроков (сейчас 15) | `server/src/index.js`, обработчик `/join` |
| Сколько раундов (пока максимум 7) | `server/src/index.js`, команда `next_round` |
| Как определяются места (сейчас приблизительно половина игроков) | `server/src/index.js`, блок `/join`; ручная настройка — `set_seats` |
| Какие существуют категории | `server/src/content.js`, массив `CATEGORIES` и `DEFAULT_PACK.categories` |
| Русские названия категорий в программе | `client/src/model.rs`, функция `category_name` |
| Правила открытия карт | `server/src/index.js`, команда `reveal` |
| Генерация кубика | `server/src/index.js`, команда `roll` |
| Голосование и результаты | `start_vote`, `vote`, `finish_vote` |
| Исключить / вернуть персонажа | `set_active` |
| Название и размеры окна | `client/src/main.rs` |
| Цвета, кнопки, экраны, панель ведущего | `client/src/app.rs` |
| Адрес API по умолчанию | `client/src/model.rs`, `LocalConfig::default()` |
| Наборы по умолчанию | `server/src/content.js` |
| Пример личного пака | `client/packs/demo.json` |

Новые игровые действия добавляй **в паре**: серверная ветка в `Room.webSocketMessage()` + кнопка/обработчик `self.send(...)` в `client/src/app.rs`. Для изменений формата ответов также поправь `client/src/model.rs`.

## 4. Как устроены паки

Пак — обыкновенный файл **JSON** в UTF-8, который пользователь может редактировать вручную. Пример:

```json
{
  "name": "Мой авторский пак",
  "catastrophes": ["Долгая полярная ночь нарушила жизнь городов."],
  "bunkers": ["Убежище 80 м², запасы на 8 месяцев, есть мастерская."],
  "categories": {
    "profession": ["Инженер", "Ботаник", "Геолог"],
    "hobby": ["Садоводство", "Астрономия"],
    "ability": ["Один раз открыть дополнительную свою карту"]
  }
}
```

Сейчас поддерживаются ключи: `gender`, `body`, `personality`, `profession`, `health`, `hobby`, `fear`, `equipment`, `backpack`, `fact`, `ability`.

Если поле отсутствует, `normalizePack()` берёт значения из базового демо-пака. Ограничение прототипа: наборы пока **не смешиваются как независимые включаемые аддоны**, а замещают соответствующие списки. Дополнительный редактор с удобными полями, весами выпадения, изображениями, специальными механиками и версионированием запланирован позднее.

Сейчас карта `ability` — **описание способности**, а не исполняемая игровая логика. Активацию эффектов и управление правилами нужно реализовать отдельно. Вики оригинала описывает по две спец. возможности на игрока; у нас пока одна карточка этой категории, это известное отличие прототипа.

### Импорт и экспорт

В клиенте открой «Пак — редактор JSON», укажи имя файла, например `my-pack.json`, затем:
- **Загрузить** — прочитать JSON рядом с EXE;
- **Сохранить** — записать JSON рядом с EXE;
- **Отправить пак в комнату** — ведущий отправляет данные на сервер **до старта** партии.

Можно указать абсолютный путь, но лучше хранить паки рядом с приложением. JSON проверяет сервер, а не только редактор.

## 5. Локальный запуск для разработки

### Запустить сервер

Нужны Node.js и npm.

```powershell
cd server
npm install
npm run dev
```

Wrangler обычно открывает `http://127.0.0.1:8787`. При проблемах со сторонними IP проверь вывод терминала.

### Запустить клиент

Нужен актуальный Rust toolchain. На Windows нужен соответствующий MSVC toolchain, который настраивается стандартной установкой Rust и Visual Studio Build Tools.

```powershell
cd client
cargo run
```

Открой два экземпляра клиента, создай комнату в первом, введи код во втором. Для начального тестирования достаточно **двух игроков**. Голос можно вести через Discord отдельно.

### Опубликовать комнатный сервер на Cloudflare

```powershell
cd server
npm install
npx wrangler login
npm run deploy
```

После успешной публикации Wrangler покажет URL Worker, например `https://murr-bunker-api.<твой-subdomain>.workers.dev`. **Подставь свой реальный адрес** в поле сервера клиента. Не нужно хранить ключи Cloudflare в GitHub.

> Cloudflare Durable Objects — отдельная услуга с лимитами и тарифами. Не обещаем неограниченную бесплатную работу: контролируй использование в Cloudflare Dashboard.

## 6. Как собрать ZIP и портативный EXE без установки Rust

В GitHub выбери **Actions → Build portable Windows client → Run workflow** или отправь коммит в `main`, затрагивающий `client/`.

После **успешного** запуска внизу страницы workflow появится Artifact **Murr-Bunker-Windows-x64**. В нём лежит ZIP с:
- `Murr-Bunker.exe`;
- `pack-example.json`.

Распакуй ZIP в любую папку и запусти EXE. **Установщика нет**, WebView2 не требуется. Размер готового файла зависит от версии библиотек и сборки. Файл с локальными настройками `murr-config.json` создаётся рядом с EXE по кнопке «Сохранить настройки».

**Сборка через Actions не публикует сервер автоматически:** сервер развёртывается отдельно командой `npm run deploy`.

## 7. Что уже есть, а чего ещё нет

### Реализовано в исходниках прототипа

- Создание комнаты, вход по коду и подключение WebSocket.
- Ник игрока и роль ведущего, до 15 участников.
- Тестовый старт от двух человек, раунды, количество мест.
- Случайный катаклизм, бункер и 11 категорий характеристик.
- Скрытые персональные карты и их раскрытие.
- Серверный кубик, голосование, ручное исключение/возвращение.
- Временный интерфейс, редактирование и импорт/экспорт JSON-пака.
- Workflow сборки Windows, базовые тесты содержимого паков.

### Не реализовано / не проверено

- Все правила, тонкие эффекты, профессиональные и специальные возможности оригинала.
- Автоматическое применение результатов голосования и полноценный финал.
- События, достижения, статистика, история игр, аккаунты, перенос ведущего.
- Полноценная система подключаемых паков, визуальный редактор и иллюстрации.
- Автопереподключение после перезапуска EXE, управление сроком жизни комнат.
- Проверенная на реальных устройствах сборка и многопользовательское тестирование — смотреть Actions и проверять вручную.

## 8. План следующей доработки

1. **Проверить Windows Actions**: исправить ошибки компиляции, если появятся; запустить два клиента и Cloudflare Worker локально.
2. **Довести основу игры**: этапы раскрытия, правила раундов, ведущий, голосования, исключения, таймеры, конец партии.
3. **Паки 2.0**: несколько паков, приоритеты, валидатор, метаданные, редактирование без JSON, спец. возможности как действия.
4. **Качественная сетевая часть**: переподключение, сохранение ID, управление токенами, защита от спама, удаление неактивных комнат.
5. **Твой дизайн**: заменить `client/src/app.rs` на полноценный визуал, добавить ресурсы в `client/assets/` и иконку приложения.
6. **По желанию — веб-версия**: сохранить сервер и общий протокол, создать отдельный браузерный клиент.

## 9. Осторожность при изменениях

- Не сохраняй приватные токены комнат, ключи Cloudflare или `.env` в репозитории.
- Токен комнаты сейчас передаётся в URL WebSocket: это удобный **MVP**, но перед публичным релизом нужно исключить его попадание в журналы и пересмотреть механизм доступа.
- Любое действие ведущего надо проверять **на сервере**, а не только скрывать кнопку в UI.
- Контент оригинального сайта используй как **ориентир механик**, а не как исходный материал для копирования чужих текстов, изображений или платных паков.
- Для экспериментов создавай отдельную ветку GitHub, чтобы рабочую `main` можно было легко восстановить.
