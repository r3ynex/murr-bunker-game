# Реализация PDF-макета Бункера (первая итерация)

Источник дизайна: пользовательский 5-страничный макет \`unkerUI.pdf\`. UI реализуется в нативном Windows-клиенте на Rust/egui; мобильный веб-интерфейс остаётся тестовым.

## Соответствие страницам макета

1. **Игровой экран:** большой блок катаклизма с фоном и описанием, кнопки навигации по разделам, данные о бункере, блок событий (WIP), личное досье с замками, таблица игроков и отдельная таблица двух спецвозможностей. Таблицы имеют горизонтальную прокрутку и формируются по числу реальных участников.
2. **Оверлеи:** выбор одного из 12 временных аватаров; ввод кода комнаты; навигация по игровой странице.
3. **Первый вход:** ник + аватар. При пустом нике генерируется \`Выживший #100..9999\`; без выбранного аватара выбирается случайный. Данные сохраняются в \`murr-config.json\` рядом с EXE.
4. **Лобби:** код комнаты, аватары, корона ведущего, зелёный/красный индикатор готовности. Гость нажимает «Готов», ведущий может начать при наличии двух и более игроков, если готовы все гости.
5. **Главное меню:** присоединение по коду, создание комнаты с выбором JSON/ZIP, окно настроек (WIP).

## Ведущий

В таблицах кнопка \`⋯\` рядом с карточкой открывает редактор: изменить текст, раскрыть карту всем или перегенерировать из выбранного пака. На стороне сервера все команды авторизованы только ведущему. Если карта уже открыта, перегенерация не закрывает её вновь.

Отдельное окно ведущего: вместимость, статус игроков (исключить/вернуть), следующий раунд, голосование, завершение и смена пака до старта. Голосование **не исключает игроков автоматически** — это сознательный выбор до реализации способности спасения от исключения.

## Пак в ZIP (необходимой установки у гостей нет)

У нас остаётся **один JSON-файл** как источник игрового контента. Если нужны изображения, его можно поместить в ZIP:

\`\`\`text
my-party.zip
├── pack.json                 Модульный Murr Pack v2
└── assets/
    └── catastrophe.png      Опциональный фон катаклизма
\`\`\`

Поддерживаются \`.png\`, \`.jpg\`, \`.jpeg\`, \`.webp\` внутри \`assets/\`. Имя главного фона — \`assets/catastrophe.png\` (допускается другое расширение). Сейчас интерфейс автоматически применяет **только фон катаклизма**, а остальные изображения архив сохраняет для следующих расширений. Внешние изображения не загружаются.

1. Ведущий выбирает ZIP до старта (главное меню → создать игру → выбрать пак, либо настройки в лобби).
2. Клиент загружает архив в Cloudflare Worker по HTTPS, авторизация токеном ведущего.
3. Сервер валидирует архив, проверяет \`pack.json\`, хранит ZIP в Durable Object конкретной комнаты и рассылает участникам метаданные (SHA-256).
4. Клиенты автоматически скачивают ZIP и отображают фон. **Никому не нужно вручную устанавливать пак**.
5. Сервер не раздаёт ZIP без токена участника этой комнаты.

Ограничения первой версии: ZIP до 2 МБ, суммарные распакованные данные до 6 МБ, не более 48 элементов. Разрешены только \`pack.json\` и изображения \`assets/\`. Исполняемые файлы, пути за пределами \`assets/\` и шифрованные ZIP не принимаются. Это небольшой прототип для дружеских игр, а не публичное хранилище произвольных больших модпаков. Перед публикацией паков нужны права на использование изображений.

**Важно:** пользователю не нужно распаковывать архив, но для ручного редактирования JSON удобнее держать незапакованный исходник и упаковывать его перед игрой.

## Шрифт

В веб-клиенте подключается Manrope через Google Fonts. Нативный клиент при запуске ищет **установленный Manrope** в системных и пользовательских каталогах Windows; если он не установлен, используется встроенный читаемый шрифт egui. Файлы шрифта не хранятся в репозитории.

## WIP — следующие этапы

- Финальная графика аватаров вместо встроенных цветных значков.
- Настоящие лёгкие и сложные события (ползунок вероятности сейчас сохраняется, но не запускает события).
- Расширенные действия ведущего над бункером и сценариями.
- Автоматизация эффектов особых возможностей и исключения по итогам голосования (пока только ручная модерация).
- Настройки визуала/горячих клавиш, итоговая оценка выживаемости и художественный эпилог.
- Отдельные фоновые иллюстрации для других секций и дополнительные вложения в ZIP.
- Точная доводка макета по размерам и отступам после пользовательского тестирования.

## Антивирус и выпуск EXE

Ранее локальный файл \`Murr-Bunker.exe\` был помечен Microsoft Defender как \`Trojan:Win32/Bearfoos.B!ml\`. Это **не доказательство ложного срабатывания**. Не отключайте Defender и не добавляйте исключения для Бункера. Сохраняйте файл в карантине до проверки.

Windows Actions собирает проект из исходников через \`cargo check\` и \`cargo build --release\`, после чего добавляет \`Murr-Bunker.exe.sha256.txt\` в ZIP-артефакт. Хеш нужен для проверки соответствия скачанного EXE результату CI, но сам по себе **не подтверждает отсутствие вредоносного кода**. Если Defender продолжает обнаружение, отправьте файл в Microsoft Security Intelligence на анализ возможной ошибочной классификации.
