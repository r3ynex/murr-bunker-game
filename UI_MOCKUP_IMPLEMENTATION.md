## Сетевые правила

- Стейт и раздача карт принадлежат Cloudflare Durable Object, а не клиенту.
- Событие set_ready передаёт булев ready; старт разрешён только при готовности всех участников, кроме нажавшего Start владельца.
- Аватар передаётся как avatarId (индекс встроенной галереи); позже можно добавить ресурсы из пака.
- GM-редактирование карты через gm_set_card проверяет владельца на сервере, обновляет значение и статус открытия; закрытые значения посторонним не отправляются.
- В лобби leave удаляет игрока и передаёт владение следующему. Выход после старта отдельно согласовываем.
- Голосование считается автоматически, исключает или возвращает игрока только ведущий вручную.

## Предлагаемая автораздача ZIP-паков — ещё НЕ реализована

Формат .bunkerpack — ZIP с pack.json + assets/ (PNG/JPEG/WebP). Сам JSON остаётся v2 с meta, roles, characteristics, items, world, customCategories. Например: assets/catastrophes/storm.webp.

1. Владелец загружает ZIP через отдельный авторизованный HTTP endpoint до запуска партии (не по WebSocket).
2. Worker проверяет права, размер и распакованный лимит, структуру путей и whitelist изображений. Запретить HTML, SVG с потенциальными скриптами, исполняемые файлы и обход каталогов (../).
3. Сервер сохраняет публичный manifest и SHA-256 версии; для больших ресурсов нужен R2, для малых — хранилище с учётом ограничений Cloudflare.
4. Остальные игроки автоматически скачивают недостающие файлы HTTPS и кешируют их по хешу. Никакой ручной установки.
5. Ни pack.json, ни публичный manifest не содержат персонально выпавших закрытых карт. Приватные значения приходят только через авторизованный WS.
6. После старта пак фиксируется; новые ревизии — только перед следующей партией.

## Как будет работать панель ГМа

В таблице нажатие ✎ открывает одно поле замены, необязательную галочку раскрытия и кнопку подтверждения. Если карта другого игрока закрыта, оригинальное значение ведущему не раскрывается. Для пакетных правок планируется отдельное окно. На сервере все изменения проверяются независимо от UI.

## Нужно согласовать позднее

- Ведущий: одновременно игрок или отдельный наблюдатель? Это влияет на права доступа к закрытым картам и способностям.
- События: шанс на каждый раунд или категории с условиями?
- Собственные аватары в паке: да/нет, максимальные размеры и форматы.
- Вторая спецвозможность: две независимые карточки или один составной тип?

## Замечания

Пока ZIP-паки и медиа ещё WIP, из интерфейса применяется прежний JSON-пак через существующую серверную команду set_pack. Авторский PDF не встроен как изображение в приложение: интерфейс собирается нативно на egui, чтобы сохранить масштабируемость.
