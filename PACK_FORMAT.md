# Murr Pack v2 — один JSON, понятные разделы

**Главная идея:** редактируешь **один файл**, внутри него карты сгруппированы по смыслу. Никаких десятков файлов и обязательной «сборки» — в лобби просто загрузи этот JSON.

[Полный пример пака](packs/starter.json) · [Импорт и проверка](tools/pack.mjs)

## Структура

```text
my-pack.json
├── formatVersion: 2
├── meta                  Название, ID и описание пака
├── roles                 Профессии и специальные возможности
│   ├── profession
│   └── ability
├── characteristics       Характеристики персонажа
│   ├── gender            Пол и возраст
│   ├── body              Телосложение и рост
│   ├── personality       Черты характера
│   ├── health            Здоровье
│   ├── hobby             Хобби
│   ├── fear              Фобии
│   └── fact              Дополнительные сведения
├── items                 Предметы и вещи
│   ├── equipment         Крупный инвентарь
│   └── backpack          Рюкзак
├── customCategories      Произвольные дополнительные карты
└── world                 Катастрофы и устройство бункера
    ├── catastrophes
    └── bunker
        ├── description
        ├── location
        ├── construction
        ├── rooms
        ├── contents
        ├── supplies
        ├── duration
        └── size
```

Любая категория необязательна: если её нет, сервер заполнит её демонстрационными значениями (для основных 11). Чтобы сделать полностью собственный пак, заполни все основные разделы.

## Минимальный пример

```json
{
  "formatVersion": 2,
  "meta": {
    "id": "my-party",
    "name": "Мой Бункер",
    "description": "Пак для компании друзей"
  },
  "roles": {
    "profession": [
      {
        "title": "Инженер",
        "stage": "Опытный",
        "description": "Умеет чинить генераторы."
      }
    ],
    "ability": ["Один раз предложить повторное голосование"]
  },
  "characteristics": {
    "health": [
      { "title": "Идеально здоров" },
      { "title": "Аллергия на пыль", "stage": "Лёгкая степень" }
    ],
    "body": [
      { "title": "Крепкое", "height1": 165, "height2": 195 }
    ],
    "gender": [
      { "title": "Женщина", "age1": 21, "age2": 45 }
    ]
  },
  "items": {
    "backpack": ["Фонарик", "Семена растений"],
    "equipment": ["Генератор", "Складная теплица"]
  },
  "customCategories": {
    "talent": {
      "label": "Скрытый талант",
      "cards": ["Очень быстро учится", "Прекрасно ориентируется"]
    }
  },
  "world": {
    "catastrophes": [
      {
        "title": "Солнечная буря",
        "description": "Повреждена электрическая инфраструктура."
      }
    ],
    "bunker": {
      "rooms": ["Мастерская и спальня"],
      "location": ["Под заброшенной обсерваторией"],
      "supplies": ["Еды на год"]
    }
  }
}
```

Каждая карта — это либо **строка**, либо **объект** с подробными параметрами. Для обычных вещей строки удобнее.

## Поля карточки

| Поле | Значение |
|---|---|
| `title` | Основной текст (обязательный у объекта) |
| `description` | Пояснение, особенности профессии, описание катаклизма |
| `stage` | Стаж профессии / степень заболевания / уровень хобби |
| `age1`, `age2` | Диапазон возраста (от и до); применяется к `gender` |
| `height1`, `height2` | Диапазон роста в см; применяется к `body` |
| `weight` | Относительная частота выпадения (по умолчанию 1) |
| `tags` | Массив меток, например `["медицина", "редкое"]` |
| `id` | Необязательный уникальный ID для удобства редактора |
| `timer` | Длительность катаклизма в секундах; хранится, но автоматического таймера пока нет |

### Вероятность выпадения

`weight` задаёт **вес**, а не проценты. Если две карточки имеют веса 3 и 1, первая будет выпадать примерно втрое чаще второй.

### Бункер и катастрофы

`world.catastrophes` — массив катаклизмов.

`world.bunker` — объект с отдельными массивами по описанным выше разделам. Сервер берёт одну случайную запись из **каждого указанного раздела** и формирует текстовое описание бункера.

### Свои категории

`customCategories` позволяет добавить, например, «Скрытый талант», «Фракция», «Класс», «Секрет». Ключи пишутся латиницей в нижнем регистре (`talent`, `faction`); человекочитаемое название идёт в `label`.

Карты из новых категорий будут **выдаваться игрокам**. Это не просто декоративные блоки.

## Импорт паков Бункер Онлайн и старого формата

Твой экспорт Бункер Онлайн имеет категории `spec`, `profession`, `health`, `sex`, `bunkerBedroom` и т. д. непосредственно **в корне** файла. Они не совпадают с нашими секциями.

В игру такой JSON можно загрузить напрямую: сервер импортирует его при отправке в лобби. Для превращения в **наш удобный однодокументный формат**:

```bash
node tools/pack.mjs import "Бункер 6.json" --out packs/imported.json
```

В итоге получишь **один файл `packs/imported.json`** с `roles`, `characteristics`, `items` и `world`. Импорт сохраняет тексты, стажи/степени, диапазоны возраста и роста. Служебные идентификаторы и временные метки сайта, не нужные нашей игре, отбрасываются. Импорт не гарантирует, что текстовые способности смогут автоматически исполняться — это пока правила для ведущего.

Если был прежний простой формат с `categories` / `catastrophes` / `bunkers`, его тоже можно перевести:
```bash
node tools/pack.mjs convert old-pack.json --out packs/converted.json
```

**Проверка файла:**

```bash
node tools/pack.mjs check packs/starter.json
```

**Создать свой пак на основе примера:**

```bash
node tools/pack.mjs init packs/my-party.json
```

Все команды требуют Node.js 22+ и не устанавливают дополнительные зависимости.

## В игре

В Windows-клиенте: **Пак → Редактор JSON** (доступен в лобби ведущему). В браузерном тестере: **Свой пак (JSON / импорт)**. Загрузи или вставь JSON, затем нажми кнопку отправки пака **до начала партии**.

**Сейчас есть:** раздельные смысловые секции **внутри одного файла**, пользовательские категории, текстовые описания и стажи, возраст/рост, веса, импорт оригинальных экспортов, обратная совместимость со старым форматом. **Пока нет:** полноценного графического редактора карточек, автоматического выполнения спецвозможностей, показа тегов и отдельного интерфейса для каждой секции. Это последующие этапы.

Сервер проверяет входной JSON перед применением. Пользовательский текст рассматривается только как текст и не выполняется как скрипт.
